# Практичне заняття No1

## Тема
Системи числення і машинне представлення даних.

## Варіант No5
- `N = 76`
- `F = 0.6`
- `A = -40`, `B = -20`
- `C = 0.5`

## 1. Переведення чисел

### Ціле число `N = 76`

Ділення з остачами:

- Основа 2: `76 / 2 = 38`, остача `0`; `38 / 2 = 19`, остача `0`; `19 / 2 = 9`, остача `1`; `9 / 2 = 4`, остача `1`; `4 / 2 = 2`, остача `0`; `2 / 2 = 1`, остача `0`; `1 / 2 = 0`, остача `1`.
  Остачі у зворотному порядку: `1001100`, отже `76 = 1001100₂`.
- Основа 8: `76 / 8 = 9`, остача `4`; `9 / 8 = 1`, остача `1`; `1 / 8 = 0`, остача `1`.
  `76 = 114₈`.
- Основа 16: `76 / 16 = 4`, остача `12 = C`; `4 / 16 = 0`, остача `4`.
  `76 = 4C₁₆`.

### Дріб `F = 0.6`

Послідовне множення на 2:

- `0.6 * 2 = 1.2`, перша цифра `1`, залишок `0.2`;
- `0.2 * 2 = 0.4`, друга цифра `0`;
- `0.4 * 2 = 0.8`, третя цифра `0`;
- `0.8 * 2 = 1.6`, четверта цифра `1`, залишок `0.6`;
- `0.6 * 2 = 1.2`, п'ята цифра `1`;
- `0.2 * 2 = 0.4`, шоста цифра `0`.

Отже, з точністю до 6 розрядів: `0.6 ≈ 0.100110₂`.

## 2. Конвертери

Функції `ConvertInteger` і `ConvertFraction` реалізовано в [Program.cs](Program.cs). Вони перевіряють допустимість основи від 2 до 16 і дають результати з пункту 1.

## 3. Додатковий код

Для 8 біт:

- `-40`: `40 = 00101000₂`; інверсія `11010111`; плюс 1: `11011000₂`.
- `-20`: `20 = 00010100₂`; інверсія `11101011`; плюс 1: `11101100₂`.

Додавання:

```text
  11011000  (-40)
+ 11101100  (-20)
-----------
  11000100  (-60)
```

Старший біт результату дорівнює 1, результат є від'ємним: інверсія `00111011` плюс 1 дає `00111100 = 60`, отже сума `-60`. Переповнення немає, оскільки сума двох від'ємних чисел залишилася від'ємною і лежить у діапазоні 8-бітного додаткового коду `[-128; 127]`.

## 4. IEEE 754 single для `C = 0.5`

Нормалізація:

```text
0.5 = 1.0 * 2^(-1)
```

- Знак: `0`.
- Порядок: `p + 127 = -1 + 127 = 126 = 01111110₂`.
- Мантиса: `00000000000000000000000`.

Повний 32-бітний запис:

```text
0 01111110 00000000000000000000000
```

Відновлення: `(+1) * 1.0 * 2^(-1) = 0.5`.

## 5. Похибка дробів

У програмі обчислено:

```text
0.1 + 0.2 = 0.30000000000000004
0.1 + 0.2 == 0.3 -> False
```

Причина полягає в тому, що `0.1`, `0.2` і `0.3` не мають скінченного двійкового запису та зберігаються з округленням.

## Контрольний вивід програми

Основні рядки виводу:

```text
Основа 2: 1001100
Основа 8: 114
Основа 16: 4C
Двійкові розряди: 0.100110
-40 = 11011000
-20 = 11101100
Сума бітів: 11000100
Десяткова сума: -60
Переповнення: False
Біти: 0 01111110 00000000000000000000000
Відновлене значення: 0.5
0.1 + 0.2 = 0.30000000000000004
Очікуване 0.3, рівність: False
```

## Висновок

Числа `-40` і `-20` у 8-бітному додатковому коді дають `-60`, тому переповнення не виникає. Число `0.5` представляється у форматі IEEE 754 single точно, а десяткові дроби на зразок `0.1` і `0.2` зазвичай округлюються під час зберігання, через що оператор рівності може дати `False`.
